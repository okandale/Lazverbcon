# Static website and Cloudflare Pages

Implemented on `codex/static-export`, branched from `codex/remake` at `6af6c42`.
The API/Docker deployment remains available. Neither branch needs to be merged
or the existing website replaced to test this version.

## What runs where

1. Locally, Python generates the complete SQLite catalog from the rules and lexicon.
2. The exporter writes a verb directory, one file per verb/dialect, and partitioned
   search indexes. Validation decisions are generated by Python too and shared
   between entries with identical restrictions.
3. Vite builds the existing website with the static query adapter enabled.
4. Upload the resulting directory to Pages. Cloudflare serves ordinary files;
   the browser selects the requested conjugations and assembles search results.

The public deployment needs no FastAPI process, SQLite database, Worker, D1 or
Python runtime. It retains verb search, forward conjugation, all options,
reverse lookup, suggestions, shared selections and all content pages. Feedback
continues to use the existing Google Apps Script destination directly.

The Python engine remains the source of truth. There is no JavaScript rewrite of
its linguistic rules. A future editor can change source definitions, regenerate,
verify and publish a new release.

## Build

Prerequisites: Python 3.11+ (tested with 3.14), Node 24+, pnpm 11.25.0. From the
repository root, set up dependencies if needed:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
pnpm --dir apps/web install --frozen-lockfile
```

Use an existing **full** catalog generated from the current engine and lexicon:

```bash
.venv/bin/python scripts/build_static.py \
  --database artifacts/cleanup-2026-10-01.sqlite \
  --output artifacts/pages
```

If you need a fresh catalog, use a new filename (published databases are immutable):

```bash
.venv/bin/lazcon build --output artifacts/release-static.sqlite
.venv/bin/python scripts/build_static.py \
  --database artifacts/release-static.sqlite \
  --output artifacts/pages
```

The builder checks catalog completeness, matching engine/lexicon revisions, data
checksums and Pages file limits. It replaces an existing generated site only after
its replacement builds successfully. It refuses to overwrite unrelated directories.
For UI-only rebuilds, reuse the exported data from the previous build:

```bash
.venv/bin/python scripts/build_static.py \
  --data artifacts/pages/data/103fa843388fca222dbe \
  --output artifacts/pages
```

Replace the release ID with the directory in your build. This preserves the data
release; source/rule changes require rebuilding the catalog and exporting again.
`artifacts/` and `lewis-upload/` stay Git-ignored. Upload only `artifacts/pages`.

## Preview locally

```bash
pnpm --dir apps/web exec vite preview \
  --outDir ../../artifacts/pages --host 127.0.0.1 --port 8001
```

Open [the static prototype](http://127.0.0.1:8001/conjugator?lang=en).
Vite is only a local file server. It is not part of the hosted deployment.
For an exact local check of Pages redirects and headers, you can instead run:

```bash
npx wrangler@4 pages dev artifacts/pages --port 8001
```

## Upload a test site to Cloudflare Pages

Run these commands on your computer, in the repository root:

```bash
npx wrangler@4 login
npx wrangler@4 pages project create lazuri-static-test --production-branch main
npx wrangler@4 pages deploy artifacts/pages \
  --project-name lazuri-static-test \
  --branch static-preview
```

Choose another project name if that name is taken. `login` opens the browser for
Cloudflare authentication. Project creation is a one-time step; for later uploads,
run only the deploy command. Wrangler prints the preview URL. `static-preview`
is a Cloudflare deployment label; it does not switch or merge the Git branch.
These commands create a separate test project and preview deployment.

Use Wrangler for this release: the output has more than 1,000 files, which exceeds
the dashboard drag-and-drop limit. Wrangler supports 20,000 files and 25 MiB per
file. No build command or backend environment variables are needed for a direct
upload. If you want Git-triggered Cloudflare builds later, create a separate Git
integration project; Cloudflare does not let a Direct Upload project switch to
Git integration.

Sources: [Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/),
[Wrangler Pages commands](https://developers.cloudflare.com/workers/wrangler/commands/pages/).

After upload, check:

- Open `/conjugator?lang=en` directly; “doguru — to learn” should display forms.
- Search `dovi` in Find a verb; select `doviba` and open a result in the conjugator.
- Try optional prefixes, subject/object combinations, and both languages.
- Refresh a phrase guide URL and open a keyboard image.
- Submit a real feedback report if you want to confirm delivery from the new host.

## File layout and cache behaviour

```
artifacts/pages/
  index.html, 404.html, _redirects, _headers
  assets/                         # JS and CSS
  images/                         # Existing public images
  data/<content-release-id>/
    manifest.json                 # File routing, normalization, sizes and hashes
    entries.json                  # 327 lexical identities
    validation.json               # Generated option/restriction decision tables
    verbs/<entry-id>/<dialect>.json
    exact/                        # Form lookup and prefix suggestions
    alternate/                    # Spelling equivalents → exact spellings
    broad/                        # Broader spelling equivalents → exact spellings
```

Forward files deduplicate form text and encode grammatical choices as integer
keys. Search indexes hold references into these files instead of copying complete
analyses repeatedly. Their sorted range directory lets the browser load only the
relevant partitions. Suggestions continue into the next partition when needed.

The JavaScript build pins a content-derived release directory. Data and compiled
assets use immutable cache headers. The browser retains a bounded cache of fetched
JSON; it never loads the entire catalog. Very common or broad searches can load
several verb files. Long-lived tabs may need a reload after a new deployment if a
previous release's uncached file is no longer available; failed loads show a retry/
reload message rather than falling back to a different data release.

Explicit page rewrites preserve deep links. `404.html` disables Pages' blanket SPA
fallback so absent data/assets stay HTTP errors. See
[Serving Pages](https://developers.cloudflare.com/pages/configuration/serving-pages/),
[redirects](https://developers.cloudflare.com/pages/configuration/redirects/), and
[headers](https://developers.cloudflare.com/pages/configuration/headers/).

## Verification

To keep a separate export and verify it exhaustively:

```bash
.venv/bin/lazcon export-static \
  --database artifacts/cleanup-2026-10-01.sqlite --output artifacts/static-data
.venv/bin/python scripts/verify_static.py \
  artifacts/static-data artifacts/cleanup-2026-10-01.sqlite
```

Choose a new export directory if one already exists. The verifier checks all
catalog requests/forms, exact search references, alternate/broad index mappings,
and every canonical request from the frozen maintainer dump fixture.

For browser-query parity:

```bash
.venv/bin/python scripts/static_test_cases.py artifacts/static-full-test \
  --database artifacts/cleanup-2026-10-01.sqlite
LAZ_STATIC_TEST_DIR=../../artifacts/static-full-test \
LAZ_STATIC_DATA=../../artifacts/static-data \
pnpm --dir apps/web exec vitest run src/api/static.integration.test.mjs
```

The fixture contains expectations from FastAPI, independently of the TypeScript
adapter. CI also builds a smaller catalog with intentionally tiny index partitions
to check boundary-spanning suggestions, then runs the full export verification and
uploads the finished site as the `cloudflare-pages` Actions artifact.
